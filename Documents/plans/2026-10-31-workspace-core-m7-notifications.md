# Workspace core M7 — Notifications, email preferences, reminders, weekly digest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members get a real inbox — every in-app notification M1–M6 already writes (assigned, invitation accepted, sprint started, event invited/rescheduled/cancelled) is listed, counted in a shell badge and marked read (US-F1, F2). Each user chooses which emails they receive and in which time zone, and the worker sends a daily due-soon/overdue reminder and a Monday weekly digest per workspace. The Phase 1 docs are closed out.

**Architecture:** Two migrations. `0028_notification_reads.sql` adds SECURITY DEFINER `spark.ws_*` reads and writes over `notifications` and `notification_preferences` (the runtime role has no grants on either table, 0002). `0029_scheduled_emails.sql` adds a `scheduled_emails` ledger (one row per user × job × period) and `spark.worker_*` functions the worker uses to claim due work under an advisory lock, read the email content and settle the row. Fastify routes in `src/routes/workspace/notifications.ts`; worker jobs in `src/modules/jobs/` run from the existing `src/worker.ts` loop next to the outbox dispatcher; two new email templates. Frontend: `/notifications` on real data, `useUnreadCount` + shell badge, `/settings/notifications`.

**Tech Stack:** PostgreSQL 18 (hand-written SQL migrations), Fastify 5 JSON-schema routes, pg, nodemailer (existing `EmailSender` port), Vitest; Next.js 16.3 / React 19 client components, plain CSS, Vitest + Testing Library.

**Spec:** `Documents/product/workspace-core-design.md` — "Cross-cutting decisions", "Email delivery" (Preferences, Schedules, Worker process, Delivery records) and milestone **M7**. Conventions: M6 plan (`2026-10-30-workspace-core-m6-schedule.md`). Migration numbers in the spec are indicative; **M7 uses `0028` and `0029`**.

## Global Constraints

- English only in code, copy, docs, commits.
- REST rules: problem+json via `problem()`; `Cache-Control: private, no-store` on every authenticated response; origin guard on non-GET; schemas `additionalProperties: false` with unknown keys rejected; uniform 404 `notification_not_found` for unknown ids, ids of other users and ids in workspaces the actor no longer belongs to.
- Writes and reads of `notifications`/`notification_preferences` go through `spark.ws_*` functions: `LANGUAGE plpgsql|sql SECURITY DEFINER SET search_path = ''`, `REVOKE ALL … FROM PUBLIC`, `GRANT EXECUTE … TO spark_app`; actor = `spark.require_session_actor()`. Worker functions are `spark.worker_*`, granted to `spark_worker` only. Input violations raise ERRCODE `22023` with a whitelisted message.
- **Visibility rule (spec):** a notification is visible to the actor iff `recipient_user_id = actor AND tenant_id = ANY(spark.session_workspace_ids())` — leaving a workspace hides its notifications (they are not deleted; rejoining shows them again).
- **Mark read:** `PATCH /notifications/{id}` `{ "read": true }` → 204, idempotent (already read → 204, `read_at` unchanged); `PATCH /notifications` `{ "read": true, "before": <ISO instant> }` → 200 `{ "updated": n }`, marks the actor's visible unread rows with `created_at <= before`; `read: false` is not supported (schema `const: true`). Foreign ids → 404 and no row changes.
- **Preferences:** kinds `task_assigned`, `due_reminders`, `weekly_digest`, channel `email`, default enabled (no row = enabled). Invitations and account mail always send and are not listed. The preference document also carries the user's `timezone` (IANA, validated by `spark.valid_timezone`), because reminders and the digest run in it.
- **Schedules (spec):** due reminder — once per local day at or after 08:00 in `users.timezone`, for users with at least one open task assigned to them in an active workspace (active membership, non-archived project and issue, status category not `done`) whose `due_date <= local_date + 1` (due today or tomorrow, or overdue); one email listing all such tasks across workspaces, at most 20 rows plus "and N more". Weekly digest — Monday at or after 08:00 local, one email per (user, active workspace with at least one non-archived project): per project completion toward plan (the M5 overview rule: Scrum → active sprint window, Kanban/Waterfall → project `start_date`–`target_date`; `planPercent`/`planStatus`), completed in the last 7 days by member, at-risk (open, due within the next 3 local days) and overdue items (at most 10 each, plus "and N more"). A run missed at 08:00 catches up later the same local day; it never sends for a past day.
- **Exactly-once per period:** `scheduled_emails` unique `(user_id, job, tenant_id, period)` (tenant NULL for reminders, coalesced in the unique index); rows move `pending → sent | suppressed | failed`; claims lease `locked_until`/`lock_token` like the outbox; give up after 5 attempts (`failed`, `last_error_code`). Enumeration of due work runs under `pg_try_advisory_xact_lock(hashtext('spark.job.' || job))` so only one worker enumerates a job at a time.
- Email: templates return `{ subject, html, text }` built with `src/modules/email/layout.ts` (escaped values, plain-text alternative, footer link to `${APP_BASE_URL}/settings/notifications`); worker logs carry counts and error codes only, never addresses or task titles.
- Rate limits: `GET /notifications/unread-count` 120/min (spec); `PATCH /notifications/{id}` 120/min (cheap, idempotent, clicked per row); `PATCH /notifications` and `PUT /me/notification-preferences` 30/min (`MUTATION_RATE_LIMIT`); list and preference reads only the global limiter.
- Frontend: landing-page visual language and the M2–M6 workspace screens (`globals.css` tokens, `.sparkPrimary`/`.sparkSecondary`, initials avatars, `ws*` classes); no new dependencies; read `Spark_Core/frontend/node_modules/next/dist/docs/` before routes/layouts; motion off under `prefers-reduced-motion`; 390 px without horizontal page scroll; keyboard-operable toggles and list.
- Commands — backend (`Spark_Core/backend`): `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:database`, `pnpm build`, `pnpm db:migrate`. Frontend (`Spark_Core/frontend`): `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`. Never report an unrun check as passing.

`22023` whitelist additions (`KNOWN_INPUT_ERRORS` in `src/routes/workspace/guard.ts`): `Invalid notification cursor`, `Invalid notification limit`, `Invalid notification before`, `Invalid notification preferences`, `Invalid timezone`.

## Review Focus

1. A user who left workspace A still has unread notifications from A → they vanish from the list, the count and mark-all; `PATCH` on one of them → 404; rejoining shows them again → DB test (Task 1), route test (Task 2).
2. Mark-all races a new notification → the new one (created after `before`) stays unread; marking read twice is a no-op 204 → DB test (Task 1), FE test (Task 5).
3. A user in `Asia/Ho_Chi_Minh` and one in `America/Los_Angeles` with tasks due tomorrow → each gets exactly one reminder on their own local morning, none before 08:00 local, none twice when two workers run, none when the preference is off or the task is done/archived/unassigned by send time → DB tests (Task 3), job tests (Task 4).
4. The tab is hidden for an hour → the badge stops polling and refetches once on return; a 401 stops polling → hook test with fake timers (Task 5).
5. Someone changes their time zone at 07:00 local after the reminder already went out for that date in the old zone → no second reminder for the same local date; a user with no assigned tasks and a workspace with no projects get no email → DB tests (Task 3).

### Task 3: Scheduled email ledger and worker reads (migration 0029)

**Files:** Create `Spark_Core/backend/drizzle/0029_scheduled_emails.sql`; journal idx 29 (`when` 1792430000000, tag `0029_scheduled_emails`). Modify `tests/database/schema.integration.ts`, `Documents/architecture/database-schema.md`.

**Interfaces (SQL):**
- Table `spark.scheduled_emails(id uuid pk, created_at, updated_at, user_id uuid not null → users, tenant_id uuid null → workspaces, job text check in ('due_reminders','weekly_digest'), period date not null, status text default 'pending' check in ('pending','sent','suppressed','failed'), attempts int ≥ 0, locked_until timestamptz, lock_token uuid, last_error_code text, sent_at timestamptz)`; unique index on `(user_id, job, coalesce(tenant_id, '00000000-0000-0000-0000-000000000000'::uuid), period)`; `tenant_id` NULL iff `job = 'due_reminders'`; RLS forced with only the owner maintenance policy (no runtime grants).
- `spark.worker_claim_scheduled_emails(p_job text, p_now timestamptz, p_lock_token uuid, p_limit integer, p_lease_seconds integer) RETURNS TABLE(id uuid, user_id uuid, tenant_id uuid, period date)` — under `pg_try_advisory_xact_lock(hashtext('spark.job.' || p_job))` (not acquired → zero rows): inserts the due `pending` rows for the current period per the Global Constraints schedule (local date and local time from `p_now AT TIME ZONE users.timezone`; reminder period = local date; digest period = the local Monday, only when the local day is Monday), `ON CONFLICT DO NOTHING`, skipping users with the preference off and users/workspaces with nothing to send; then claims up to `p_limit` (1–50) `pending` rows of the job whose period is still the user's current local period and whose lease expired, setting `locked_until`, `lock_token`, `attempts + 1`. Rows of a past period that are still pending become `suppressed` (`last_error_code 'expired'`).
- `spark.worker_due_reminder_email(p_id uuid) RETURNS TABLE(status text, email text, recipient_name text, total integer, task_workspace text, task_workspace_slug text, task_key text, task_title text, task_due date, task_overdue boolean)` — `status` `pending` with one row per task (at most 20, ordered by due date then key; `total` = full count) or a single `skipped` row with NULL details when nothing is due any more, the preference was turned off, or the user/email is gone.
- `spark.worker_weekly_digest_email(p_id uuid) RETURNS TABLE(status text, email text, recipient_name text, workspace_name text, workspace_slug text, section text, project_key text, project_name text, methodology text, label text, value numeric, extra jsonb)` — one row per digest line: `section` `project` (per project: `extra` = `{ done, total, unit, windowStart, windowEnd, activeSprintName }` — the TS job computes `planPercent`/`planStatus`), `member` (completed in the last 7 days per member, `value` = count), `at_risk` and `overdue` (at most 10 each, `label` = `KEY-n title`, `extra` = `{ due, total }`); a single `skipped` row as above.
- `spark.worker_settle_scheduled_email(p_id uuid, p_lock_token uuid, p_status text, p_error_code text, p_retry_at timestamptz) RETURNS boolean` — `sent` (sets `sent_at`) / `suppressed` / retry (`pending`, lease cleared, `last_error_code`) / `failed` after 5 attempts; false when the lease was lost.
- All `worker_*` granted to `spark_worker` only.
